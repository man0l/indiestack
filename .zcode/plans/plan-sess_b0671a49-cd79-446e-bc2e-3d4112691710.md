Plan: Svelte islands — same Worker, cards = shadcn cards

Context: Current admin is a pure Worker: src/index.ts dispatch(PLUGINS,"adminSection") + src/ui.ts page/adminShell string templates, 15 plugins grouped by AdminGroup monitoring/growth/distribute/system (src/kernel/plugin.ts:10, src/kernel/catalog.ts:23). The server shell (sidebar + overview cards) already exists in src/ui.ts:171-210 and src/index.ts:141 adminOverview/collectNavCards. User asked for Svelte, same worker, drop htmx, cards = shadcn Cards.

Decision: Do NOT add SvelteKit/adapter-cloudflare. IndieStack's constraint is one Worker, migrations in migrations/, one `wrangler deploy`. The Islands pattern satisfies "Svelte" without a second deploy: keep src/index.ts as `export default {fetch,scheduled}` (wrangler.jsonc main src/index.ts), bundle Svelte with Vite @sveltejs/vite-plugin-svelte into one `dist/admin/_app/admin.js` that the Worker serves as a static asset at /_app/admin.js. No adapter, no separate admin Worker, no change to the wrangler.jsonc triggers/D1/R2.

Stack:
- deps: svelte@5, vite@6, @sveltejs/vite-plugin-svelte, tailwindcss@3, postcss, autoprefixer, lucide-svelte — all in devDependencies (keep package.json dependencies empty). No @sveltejs/kit, no adapter-cloudflare (avoids the “two Workers” problem we hit on Sep 2 when we tried svelte.config.js + .svelte-kit/ and deleted it).
- vite.config.ts: plugins [svelte()], build.rollupOptions.input = { admin: "admin/index.html" } (entry is admin/index.html -> admin/src/main.ts). outDir dist/admin, assetsDir _app. wrangler.jsonc keeps src/index.ts as main; add `assets: { directory: "dist/admin", binding: "ASSETS" }` only if we want wrangler to serve static — or simpler: Worker serves the built file from R2 (no binding) — initial pass serves inline via src/index.ts route GET /_app/admin.js reading from BUCKET asset written at build time (single command npm run build && wrangler deploy).
- Tailwind: content ["src/**/*.{ts,svelte}", "admin/**/*.{ts,svelte}"], with existing CSS vars (--bg:#0e1014 etc) mapped as tailwind theme so shadcn-svelte tokens work in dark mode.

Contract (keep plugin string fallback, add island opt-in):
- src/kernel/plugin.ts: extend Plugin.adminNav to {group,label,icon:PluginIcon} (icons already landed, src/kernel/plugin.ts:27: PluginIcon activity/heart-pulse/git-branch/...). Add optional Plugin.adminSvelte?: { component: string // path under admin/src/lib/plugins/<id>.svelte } — or simpler: if admin/src/lib/plugins/<id>.svelte exists, the server renders a <div data-island="id" data-props='{json}'> hydration shell and the Svelte mount replaces it.
- Keep existing Plugin.adminSection(): string as SSR/no-JS fallback. Islands hydrate the div.list/form.card region only; docs/curl snippets stay as server HTML inside the island.

Islands implemented:
- admin/index.html + admin/src/main.ts mount Islands: scans [data-island] nodes, fetches /api/plugins/:id?json (new Worker JSON API) for rows, then mounts Svelte component with props.
- shadcn-svelte Cards: admin/src/lib/ui/card.svelte, badge.svelte, button.svelte already copy-pasted on the failed SPA branch (admin/src/lib/ui/); reuse. Sidebar stays in Svelte (admin/src/lib/Sidebar.svelte with lucide-svelte icons) so the overview becomes a Svelte page with Card grid — but the sidebar also exists as the server shell fallback; Svelte hydrates it.

Worker API (keep gateAdmin):
- GET /api/overview → {cards} (current collectNavCards( summarized + health dots)).
- GET /api/plugins/:id → {id, html, footer} plus JSON rows for the Svelte island to avoid HTML parsing (e.g. /api/plugins/ping returns {monitors: Monitor[]} fetched via listMonitors). First island to migrate: ping (highest payoff: 20-row dense table, 14-field add form) — keep adminMonitors() string fallback until island mounts.
- Keep existing dispatch(PLUGINS,"admin") POST routes working; islands use fetch/enhance, non-JS falls back to form post.

Build & deploy:
- scripts: "build:admin": "vite build", "build": "npm run build:admin && tsc --noEmit", "deploy": "npm run build:admin && wrangler d1 migrations apply DB --remote && wrangler deploy". Local dev: `npm run build:admin -- --watch` + wrangler dev (no SvelteKit dev server).
- wrangler.jsonc: keep triggers crons * every minute, bindings DB/BUCKET/AI/APP_NAME. If using assets directory, add "assets": { "directory": "dist/admin", "not_found_handling": "single-page-application" } — but prefer inline serving via new route GET /_app/admin.js so no wrangler assets migration needed.

Risks & why not SvelteKit:
- SvelteKit + adapter-cloudflare would replace the Worker (src/index.ts) with a Kit build, break migrations dir, and require a second deploy target. Islands keeps one Worker, one wrangler.jsonc, PLAN.md constraint intact.
- Bundle size: islands share one admin.js (~40kb gz) vs 15 separate chunks — faster for overview. Code-split by dynamic import island components on demand if needed.

Deliverable: responsive Linear-dark shell (current sidebar converts to Svelte with Tailwind utilities), overview grid of shadcn Cards with live dots, per-plugin pages where the list/table is a Svelte island, server strings as no-JS fallback. Fully shippable after Phase 3 without touching plugin UIs.
